rvbench-kernel-server
下一代架构设计

将入口、调度和结果权威收口到一个 manager，把 RV64 测量能力放到可登记的 worker；保留直接加载 spec.json 的最简本地运行。

需求正本：requirements.md v0.3 · 42 条需求 / 22 个验收场景 · 本页内嵌 Archify 目标架构，无需网络加载图形资源。

01 / DECISIONS

一套执行核心，两种产品形态

局域网分布式

manager 可在 amd64、arm64、rv64 Linux 主机运行。它接收用户 Run，校验 spec，匹配能力和资源，再为 RV64 worker 签发任务租约。用户不需要知道板卡地址。

最简本地

RV64 上一个 Rust 程序直接读取 spec 与引用合同，复用同一个 Runner，调用已经安装的 Python/torch/Triton/FlagGems。无需 manager、HTTP 服务、token、战役目录或消息队列。

设计决策本版选择与原因
D-01 语言与发布用户指定 Rust。每个 Linux target 发布一个 rvbench；测试脚本、Schema、报告模板嵌入程序。科学计算依赖由目标机提供。
D-02 原生输入spec.json 是公开用例合同正本。manager 和 run 使用相同 SpecCompiler；旧 suite-v1 仅作为迁移输入，不取代 spec。
D-03 管理边界一个活动 manager 是状态权威；一个 Agent 管理每台 RV64 主机的多个资源池，替代一块板上多个独立 HTTP 实例抢安装树。
D-04 传输worker 主动发起 mTLS 长轮询。manager 在响应中派发租约；心跳/续约/结果通过同一控制服务回传。不依赖 SSH 或可入站的 worker 端口。
D-05 持久化内嵌 SQLite 保存 manager 事务状态，本地对象目录保存按摘要寻址的候选和证据；worker 保存 journal/outbox。本地 run 仅用作业文件，不要求启动数据库服务。
D-06 执行安全Subprocess 是首版最小执行器；独立候选 overlay 是首选，不能正确支持的 adapter 显式退到受控 shared-install。锁失败拒绝执行。
D-07 可信结果不声称执行恰好一次。租约、generation 和 CAS 保证只有一个有效提交；物理停止靠本地 watchdog，恢复证明是 worker 就绪与结果有效性的条件。

本次交付是设计，不是重写完成。所有命令、接口、模块和容量数字都是拟定契约；现有 evald/warmd/监控部署物保持原样。

03 / DEPLOYMENT

最简运行不绕行分布式服务

# 拟定接口：spec 及其相对引用合同由用户提供
./rvbench doctor --spec ./micro/spec.json --python /opt/flag-env/bin/python
./rvbench run --spec ./micro/spec.json --python /opt/flag-env/bin/python \
  --lane correctness --output ./run-001
# 在同一输入/环境上复用可信完成，保留全部旧尝试证据
./rvbench run --spec ./micro/spec.json --python /opt/flag-env/bin/python \
  --lane correctness --output ./run-001 --resume

Runner构造 → 测量 → 检查 → 清理

默认测当前已安装的 candidate callable 与 spec 指定 reference；--candidate candidate.bundle.json 可显式加载候选。默认 Python 从当前 PATH/已激活环境选取；找不到或版本能力不足时 doctor 与 run 都解释性失败。非 RV64 上 run 拒绝执行，不能把仿真计时当真机结果。

run 不启动嵌入式 manager，不开启网络监听。控制文件默认位于指定输出目录；私有候选 overlay、缓存与嵌入适配脚本提取目录按内容摘要生成，不能污染用户安装环境。

# manager：TLS 和用户身份必须先配置；对 LAN 监听是显式选择
./rvbench manager --config manager.toml
# 每台 RV64：管理员登记身份后，仅主动连接 manager
./rvbench worker --config worker.toml
# 客户端自动打包 spec 的相对合同闭包，提交到唯一入口
./rvbench submit --manager https://manager.lan:8788 \
  --spec ./micro/spec.json --lane timing --wait --output ./downloaded-run

manager 架构影响控制面构建，不影响 case 运行位置。worker 在 LAN 内主动拉取，由 manager 在响应中给出资源预留、Job 和 Lease；产物经过摘要校验后上传。单机只有一台 RV64 时，仍可选分布式模式，但最简 run 没有这些部署前置。

一个 Rust 二进制包含全部子命令；manager 在 RV64 上也不能隐式兼职执行。需要让同一物理机同时承担两种角色时，必须显式启动独立 worker，登记独立资源并避免控制面占用测量 CPU。

04 / RUST BOUNDARIES

按状态所有权与副作用拆模块

首版采用一个 Cargo workspace、一个发布 binary。控制面库不导入 Runner 平台实现；将 Linux/RV64 执行门禁放在 Host Driver，三种 manager 构建均不需要 Python 或科学计算库。

拟定 crate / 模块对外能力所有权 / 明确限制
rvbench-domainRun/Job/Attempt、Outcome、Version、Fingerprint、错误码纯数据与状态转换规则；不读文件、不发网络、不启动进程。
rvbench-speccompile(bundle, selection, policy) → ExecutionPlanSchema、语义、引用合同与 v1 digest 校验；只生成有明确输入/绑定/检查的计划，不导入 torch。
rvbench-manager提交、调度、资源预留、租约 CAS、结果提交唯一权威逻辑状态；不执行候选代码，不写 worker 安装树。
rvbench-agent注册/续约、接单、watchdog、reconcile、outbox一台 worker 的 boot session 和物理资源所有者；只执行有效 manager 授权。
rvbench-runnerexecute(plan, permit, cancel) → AttemptEvidence进程树、overlay、journal、测量与清理；本地/远端完全复用；不做集群调度。
rvbench-hostISA/CPU 探测、核簇入口、进程组、资源锁GenericLinux / SpacemiTK3 driver；厂商 /proc 写入只在这里；错误 fail closed。
rvbench-storeManagerStore / JournalStore / BlobStoremanager SQLite 的 CAS 事务；本地 journal 的原子文件写入；内容不可变对象与 GC。避免文件与 DB 双写隐含成功。
rvbench-protocol用户 HTTP 与 worker mTLS DTO/version传输协议和主体权限；不把状态机复制到 Handler。
rvbench-report规范化结果、分组汇总、HTML、v1 读适配从证据生成视图；不能修改执行结论、补造 null 数据或自动 promote。
rvbenchmanager / worker / run / submit / doctor / spec validateCLI 组合根。LocalDispatcher 直接组合 SpecCompiler + Runner + Reporter。

Python adapter 是运行时边界：Rust 通过版本化 JSONL 协议调用内嵌的 Python entry script，以 argv 参数和私有工作目录传递完整 CasePlan。stdout 为结构化协议，stderr 为诊断；协议行有数量/大小上限，日志另落盘，避免日志混入 JSON。具体 resolver、generator、check 通过固定注册表实现，不使用 eval 或任意动态导入。

建议依赖组合：serde/serde_json、Tokio、HTTP/TLS 组件、rusqlite bundled、clap、SHA256。选型与版本是构建验证项，不在设计文档里锁“最新版本”。SQLite C 源码在构建期编译并链接；每个 target 需要相应编译器/linker/sysroot，部署端不需要 SQLite 服务或开发包。

05 / INPUT CONTRACT

完整读取 spec.json，不回退到 shape 表

配套仓公开格式现为 schema_version=2.0.0，顶层包含必填 version（文件自身版本）与 suite / sources / policies / operators。schema_version 严格匹配 spec.schema.json 的 const；旧 suite.version 已迁至顶层，属于不兼容变更，缺版本或未知格式拒绝。独立 spec.hidden.schema.json 为 1.0.0，也必须有自己的顶层 version；两文件格式版本分别管理。当前公开/隐藏实例自身版本均为 0.2.0，仍为 draft。

一个 case 保留多输入、attrs、返回槽位与检查规则；call.args/kwargs 是绑定，python_symbol/adapter 是注册标识，不是任意可执行代码。加载时固定格式版本、自身版本与 canonical 摘要，显式转换旧文件后必须重校验并重绑定隐藏引用摘要。

1 读取输入包严格 JSON、重复键/非有限数拒绝
→
2 校验合同Schema + 跨字段语义 + 引用摘要
→
3 判定可运行ready、adapter/check/generator 能力
→
4 固定计划每 case 完整 CasePlan + 实际运行策略
SpecCompiler 必须保留Runner 的义务
inputs 的 name/kind/shape/dtype/layout/generator显式 None 与零维 tensor 区分；非连续 strides/storage_offset 真实构造，不能 contiguous 化；两臂复用同一份物化输入。
attrs 与 call.args/kwargs，candidate/reference binding保留 false/0/null，按声明绑定；未实现符号返回 unsupported，不尝试另一个算子或 shape。
returns 与 outputs，有序 tensor/tuple 槽位检查全部输出结构、shape/dtype/layout；不能只取 Flash 第一个输出或将 TopK indices 转成 float。
verification checks/rules 与 resolved contractexact/allclose/TopK/归一化等逐项证据；pending 容差不替换成 5e-3；需要的规则不齐全则不可验收。
policies.timing、来源、顶层 schema_version/version 与 execution计时合同负责同步、成本归属和统计口径；运行参数单独快照，不把“已通过”写回 spec。

输入包与摘要

CLI 以 spec 所在目录为基准，只打包 resolved contract 和显式候选引用的闭包；manager 接收 manifest {path, bytes, sha256} 与内容对象。所有引用先验证规范相对路径、无 ../绝对路径/软链逃逸，并在 worker 私有目录重建。$schema 指向输入格式时仅作标识，验证使用二进制内已锁定 Schema，不能自动联网获取任意 URL。

区分 spec_digest（rvbench-kernel v1 解析后排序紧凑 JSON）、raw_blob_digest（上传原始字节）、bundle_digest（路径与对象引用闭包）、plan_digest（所选 case + 有效运行策略）。Rust 必须用 Python 权威工具生成的固定向量验证数字、浮点指数、负零、Unicode 和 null 序列化；一般 serde_json 输出不能直接宣称兼容 Python digest。若不能一致，阻止该输入版本接入，不能自动改摘要算法。

当前 micro 文档已经标为被典型 8 集计划替代；首份 typical8 是 draft 的 8 个 C01，数值/输出合同和执行适配仍待完善。新架构支持 加载文件，不把文件格式有效当作 80 个用例已经可以执行。

正式 run 默认 ready gate。--probe 显式运行 draft 中可探测 case，所有产物标为 probe；pending/blocked/skip 全部保留在报告，不能产生正式 passed。默认不扫描 spec.hidden.json；私有输入显式授权与脱敏接口留到后续。旧 suite-v1 转换器只在能完整补全 call/input/check 合同后使用，否则报不可转换。

06 / MATCH & RESERVE

架构匹配只是接单的第一关

worker 注册上报：稳定 worker_id、boot_id、证书身份、协议/runner/adapter 版本、ISA 扩展与 VLEN（可测时）、CPU 型号与核簇、可配置核池、可用内存、runtime/安装树/合同摘要、状态与容量。manager 保存观测时间和 capability_digest；计划需要的能力不满足时明确 blocked/unsupported。

调度顺序规则
1 过滤已登记、当前 boot session、ready、RV64、所需 ISA/适配器/运行时和资源容量匹配。draining/quarantined/lost 不派新任务。
2 公平队列全局和主体上限在接受时校验；主体轮转，主体内同优先级 FIFO；Suite 逐批展开并事务保存游标，防止一个 Run 挤满 ready 队列。
3 安排资源预留具体 lane/CPU set/内存预算/安装槽位。参考+候选成对留在同 Attempt；timing 默认绑定具体 worker/environment。
4 发放租约资源预留、Attempt 创建与 lease token 在同一 SQLite 事务中提交，再给 worker；不是依赖心跳里“还有空位”立即无锁派发。
5 释放只有 worker 清理证明、完成/取消提交或已确认 boot 恢复才释放本机资源。失联只是失联，不能宣称本机已停止。

perf / timing

默认一个 timing Attempt 独占 worker 的测量资源；先 drain acc/func 再测。分核并行是显式策略，必须验证核簇、CPU/OMP、内存及厂商调度，写进 fingerprint，并纳入计时噪声验收。

acc / correctness 与 func

可配置并行池；只做数值验证或冒烟。warmup=0/rep=1，正式 speedup 置 null。shared-install 模式下路径互斥优先于 lane 并行，不因分核而绕过槽位锁。

manager 挑选最早符合条件的 case，再在允许 worker 中按已预留负载与缓存亲和选择。缓存命中只是效率提示，不能绕过硬能力、environment pin 或输入摘要。没有适配 worker 时保留可解释 queued/blocked 原因，不能静默用另一机器、另一 dtype 或仿真执行。

K3 Host Driver 在 Agent 自身的执行派生路径处理 A100/X100 与厂商入口；具体 /proc 注册和进程亲和的继承不变量先以现有 start-ai 流程做真机验证。manager 不发送 shell 片段，也不假定 taskset 能跨厂商调度域。

07 / FAILURE SEMANTICS

租约解决提交权，watchdog 解决残留执行

默认参数建议：heartbeat=5s、lease=30s、最大续约请求耗时=5s、到期前 5s 预留停机余量、最多 2 次基础设施重试。它们是可调初值，必须经 LAN 故障注入验证；长轮询领任务与续约用独立通道，不能彼此阻塞。

lease token = {
  job_id, attempt_id, worker_id, boot_id,
  manager_epoch, generation, lease_id
}

Manager Job: queued → assigned → running → cleanup → succeeded | failed | timed_out
取消路径:    queued → canceled
             assigned/running → stopping → cleanup → canceled
失联路径:    当前 Attempt → lost；Job → retry_wait | infra_error（预算耗尽）
Worker:      registering → reconciling → ready → draining
             任意清理失败 → quarantined；失联 → 不接新任务
Attempt:     preparing → executing → stopping? → cleanup → awaiting_ack → archived

网络延迟/时钟偏移不能延长本地授权。worker 以一次请求开始的本地单调时刻为续约 TTL 的起点；ACK 到达时扣除在途时间，过晚 ACK 不能复活已到期 Attempt。续约请求带单调递增 sequence；manager 只有在当前授权尚有效且未取消时续约，返回同序号/相同 epoch 的授权。旧响应、旧 sequence、已过期会话都忽略。

manager 侧租约计时也使用进程内单调时钟；持久记录供审计。manager 启动持有独占状态目录锁，事务增加 epoch，所有旧 in-flight 租约失效并进入 reconcile/retry_wait；不会凭旧 wall clock 把它们视为仍可提交。worker 发现 epoch 变化立即停进程并清理，断网时到期 watchdog 自行停机。

失败 / 竞争明确处置
任务派发后响应丢失租约已占预留容量；worker 可按 attempt_id 查询授权或重试同一领任务 request ID。manager 不创建两个可执行 Attempt 占同槽位。
manager / LAN 不可达worker 在授权到期前停止进程树并 cleanup，写 outbox；manager 将过期 Attempt 标 lost。新 worker 的重试允许发生重复计算，但旧报告不能成为权威结果。
完成报告与取消竞争manager 事务 CAS。完成先持久提交则终态不反转；取消先登记则拒绝后续 success 提交，等待清理证据后 canceled。报告重复同摘要返回原 ACK。
worker 重启boot_id 改变，新 session 接管前先 journal 恢复；旧 boot 的报告只入审计。没有恢复证明就不 ready。
旧结果延迟到达旧 token/generation/epoch 报告可作为 attempt audit 保存，但返回 stale receipt，不能覆盖 current Job。不同摘要重复提交是冲突，需人工调查。
超过恢复/重试预算Job 最终 infra_error，Run 显示未完成的 case；worker quarantined，保留候选备份与诊断，不循环重试。

fencing 不能让孤立 worker 的 CPU 自动停下来。物理执行由 Agent watchdog、进程组/PDEATHSIG 或等价监护机制负责；强杀/断电时通过重启 journal 恢复。未知 worker 不能接新任务，不能在共享安装树上假装旧执行已经消失。

08 / DURABILITY

接受成功必须先持久，可信完成必须先清理

ManagerStore

manager-data/
  state.sqlite (+ WAL)
  blobs/sha256/<digest>
  incoming/<upload-id>.tmp
  reports/<run-id>/

SQLite 保存 runs、jobs、attempts、workers、leases、resource_reservations、idempotency、events、artifact_refs。建议 WAL + synchronous=FULL，单活动 manager/单写入协调器；状态目录必须本地文件系统，不放共享 NFS。

Worker / local journal

worker-data/
  identity/ + boot session
  attempts/<attempt-id>/
    journal.json + plan.json
    backup/ + overlay/ + logs/
    result.json + cleanup.json
  outbox/ + cache/

每一次外部副作用前写 journal；记录实际路径、预期/原始/加载/恢复 SHA、进程身份和状态。按 journal fsync → 副作用 → 校验 → 下一状态推进。

跨文件与数据库的一致性

先把上传对象写临时文件，校验大小和 SHA，再在同一文件系统 fsync/原子发布；对象完整后才提交引用它的 Run/结果索引事务。DB 失败可能留下无引用对象，后台 GC 延迟回收；DB 不能指向半文件。接受 Run 的幂等键、规范化计划快照与展开游标同事务提交，返回 202 后重启仍可继续展开。

worker cleanup 完成后将 ResultEnvelope 与产物摘要写 outbox，再上传完整证据。manager 验证有效 token、清理状态与对象，再同事务完成 CAS/资源释放/事件；持久 ACK 包含 receipt_id 和 result_digest。worker 收到并落盘 ACK 后才可删除 outbox；ACK 丢失重复上传安全。过期结果若仅入审计也给持久的 stale receipt，不误称成功。

启动恢复

  1. 取得本机 data-dir 与安装根锁，拒绝双 Agent 或 run/Agent 抢同测量资源。
  2. 检查未完成 journal，按 PID + 启动时间/boot 身份验证进程，停止残留进程树，避免误杀复用 PID。
  3. overlay 删除私有副作用；shared-install 按备份与原始摘要恢复，验证每条恢复结果。
  4. 清理成功才上报 ready；无法恢复、备份缺失、磁盘损坏进入 quarantined，等待修复。绝不退成“只标 failed 然后接单”。

保留策略配置化；GC 保护 in-flight、outbox、未恢复备份和报告引用。备份与迁移包含 SQLite 在线备份或停机一致性副本及对象目录 manifest，不直接复制活跃 WAL 主文件声称可恢复。

09 / RUNNER

独立 overlay 优先，共享安装槽位明确受控

准备锁定资源、校验 plan/bundle 与当前环境
→
物化构造完整输入、绑定候选、记录加载 SHA
→
执行两臂输入复用、计时、逐输出检查
→
清理停整个进程树、恢复、验证、持久化证据

候选隔离

overlay 模式：每 Attempt 独立包视图，只读基础 runtime + 私有候选层；导入必须真实落在该视图，检查模块 origin 与候选文件摘要。PYTHONPATH 或单纯 sys.path 注入不能保证已经安装的包子模块正确替换；adapter 需要导入探针，证明 top-level binding 与所有依赖引用符合候选合同。验证不通过则拒绝 overlay 能力。

shared-install 模式：只对已验证的 adapter 开启，安装根锁/每路径锁覆盖 deploy→run→restore；并写 journal、备份原字节、临时替换与 SHA 回读。锁目录不可写直接失败，不退到进程内锁。不同旧 evald 实例、Agent 和 local run 必须使用同一根级互斥域；迁移阶段更稳妥的是停旧写者。

普通分布式评估不接受永久安装 restore=false；后续 promote 必须独立管理员权限、具体 worker pin、expected base digest、独占资源和禁止自动重试。首版只支持可清理的评估，无隐藏定稿副作用。

执行器与硬超时

Subprocess 首版直接启动固定 Python argv，避免 shell 拼接与 source 任意用户脚本。控制器在 runtime 预检时构建明确环境变量，Host Driver 负责 affinity、进程组和厂商入口。超时/用户中断/租约到期先终止再限时强杀整个树，cleanup 有单独预算；恢复失败保留 evidence 并 quarantined。

WarmFork 是可选性能层，先验证 Python/runtime 支持；父进程只预热不含候选的 torch/triton，每次 fork 子进程在新 overlay 内加载候选。Subprocess 与 WarmFork 必须通过 AT-05 语义一致性；不得用预热省时绕过启动恢复、加载摘要或清理门禁。

构造/拷贝/布局适配成本是否进入测量由 spec 绑定计时合同决定，禁止服务端自行排除。更换 dtype、给 shape 加默认值、只检第一个返回项、把未绑定容差改成宽松值都是协议错误。

11 / EVIDENCE

归档完整证据，再生成可比较的视图

结果正本使用 eval_results.json，结构见配套仓 eval_results.schema.json（Draft 2020-12），格式版本 schema_version=1.0.0、自身修订版本 version 分别必填。完整合同、语义校验器及 synthetic 示例 已落仓；Rust/Python 写入与读取仍待实现。示例不是实测数据。

结果顶层必需内容
run / specsRun ID、standalone/distributed、manager ISA、终态与 UTC 时间、measured/synthetic、可见性；公开/隐藏 spec 的 schema_version、version、canonical SHA。
execution / environmentsfunc/acc/perf、实际 warmup/rep、计时合同/选择计划/候选摘要；RV64 worker/boot、CPU/ISA/核集、软件版本与隔离 fingerprint。
cases[].attempts[]job/lease epoch、环境引用、plan/实际加载摘要；所有输入及 generator/seed、attrs、返回项、检查 method/合同/参数/metrics、成对采样、退出/清理/原因及相对产物引用。结果不包含认证 token。
selected_attempt_id有效选择必须匹配 case outcome、trusted 且 cleanup=ok；passed 要求零退出、完整返回与全部检查；acc/perf 每个返回项须数值或语义检查。
summary从全部所选 case 重算六类 outcome 与固定分母；历史重试不重复计数；有效 perf 按环境重算 median、speedup、几何平均。

run.visibility=private 保存完整隐藏证据。公开 hidden 记录必须 redacted=true，attempts=[]、selected_attempt_id=null、reason=null，仅保留身份/合同引用与 outcome；私有日志和原始 artifact 的下载同样受限。缺值为 null，未知字段/格式、缺版本、摘要不符或伪造统计均拒绝。JSON 一致性不证明租约、artifact 字节或执行发生，manager 另核对持久化 fencing 与原始证据。

结果层输出约定
case outcomepassed / failed / skipped / unverifiable / infra_error / canceled；func 只证明执行成功，不能充当数值验收。
timing保留有效 warmup/rep、同步、统计方法、reference/candidate 成对样本与原始采样；acc/func 的正式 speedup 为 null。
环境指纹worker 实例、CPU 型号/核簇/核集/ISA、runtime 与适配器/生成器版本、候选基础树、计时协议及资源隔离策略。候选摘要单独存，避免每次换候选使环境组失效。
可比性默认同 worker + 同环境 + 同 spec/case + 同协议；跨主机原始值分组展示，不能把“都是 RV64”或“都是 K3”当作可直接比。重试换机器必须重测 reference，不能继承旧 incumbent。
Run summary所选 case 总数固定；列出全部 outcome、已完成/总数、每环境统计。正确性计数可按相同合同汇总；speedup 不跨环境混合平均。
恢复与可信性cleanup_ok、loaded_digest 与 token 校验不足时不可信；旧 Attempt 和 infra failure 留证，不能覆盖 case 的有效结果。

本地目录原子写入 eval_results.json 作为结果快照正本，cases.jsonl / summary.json / report.html 为派生视图，原始逐 Attempt 证据保存在 attempts/。快照变化更新其自身 version，不改写历史证据。--resume 只复用完整匹配 plan/candidate/environment 且 cleanup_ok 的可信 case；changed spec、输入策略、运行时或候选产生新 Run，不能仅看同名 result 文件跳过。

退出码：0 满足 spec 声明验收策略；1 测试不通过或未允许 skip/unverifiable；2 输入/平台/依赖问题；3 基础设施或恢复失败；130 用户中断且清理完成。部分成功仍完整报告，其余项不会从分母消失。性能门槛若 spec 没有声明，本服务不发明“更快就是通过”。

保留 raw-v1/result-v2 读适配，并为兼容客户端提供 nullable 视图；新多输入/多输出证据不能压缩到旧 shape 字符串冒称无损。旧 registry 留在旧流程，新增 manager 不默认接管最优候选选择。

12 / TRUST & OPERATIONS

受控 LAN 服务，监控不进入执行依赖

默认实验室身份边界：manager 用户权限区分 submit/read/cancel/admin，worker 证书由管理员登记并可撤销。外部候选代码在 worker 账号权限下运行；argv/路径白名单和 Rust 本身不构成恶意代码沙箱。若后续公开接收不受信任代码，需独立 OS namespace/seccomp/cgroup/网络隔离策略与威胁模型，不能直接复用此默认信任假设。

候选与合同拒绝目录穿越、符号链接逃逸、超限上传；产物按主体与 Run 访问授权。Cache 的摘要键不赋予读权限。TLS 证书来源、续期、撤销、bootstrap CA 信任和 key 文件权限写入运维指南，不提供明文默认 token。Agent 作为无 root 账号运行；厂商调度权限通过明确 Host Driver/系统配置提供。

观测面建议指标 / 状态
manager每 lane 的 queued/assigned/running、接受延迟、调度等待、lease expiry、stale result、retry、worker ready/quarantine、对象与 DB 错误。
workerlane 预留/实际占用、CPU/内存、Attempt 阶段、watchdog 停止、loaded mismatch、restore failure、outbox backlog、runtime capability。
health存活与就绪分别报告；quarantined 表示活着但不能接单；probe 失败不可被健康 HTTP 200 掩盖。
日志与指标日志带 run/job/attempt ID；指标只用受控 lane/状态/worker 标签，不把 case_id、candidate SHA、token 和原始输入放进高基数时间序列。

Prometheus/dashboard 是可选观测客户端；无它们仍可运行和下载结果。worker 默认不需要公开网络监听，manager 通过经认证的 heartbeat 接收 worker 指标并暴露聚合视图；可选本地 loopback exporter 由运维另行启用。控制流、租约与运行本身不依赖监控抓取成功。

14 / OPEN VALIDATION

已定方向与仍需证明的边界

事项设计处置 / 验证门
Rust RV64 构建官方支持目标不等于应用依赖已验证。GNU target 起步，bundle SQLite 与 TLS crypto 的 C/汇编依赖纳入 target 编译；三平台各输出 manifest、SHA 与真机 smoke。完全静态 musl 是可选后续路线，先验证 runtime ABI 和 vendor SDK。
当前 spec 仍是 draft格式接受能力与可执行 adapter 独立交付。micro 作为例子，名称不固定；典型 8 的 ready 合同与 M2/M3 内容未完成时只探针。
跨语言 digest必须固定 Python v1 语义，特别是浮点串、Unicode/重复键与 null；失败阻止接入，不能换成普通 JSON SHA 偷过。
候选 overlay 导入证明实际 module origin/top-level binding；未证明之前 shared-install 明确独占并持久恢复。不能把 PYTHONPATH 设置当完整隔离已实现。
LAN 分区与 manager 单点manager 不可用时不接受新 Run，worker 到期停止；设计优先可审计恢复。首版没有 HA 自动选主，备份恢复重新 epoch 与登记。
计时干扰整机 timing 独占默认；分核/并发须噪声实验。manager 的 p95 目标是控制面指标，不是 benchmark 速度保证。
输入内容跨 runtime 变化generator seed 在不同 torch 版本可能不同；记录真实输入 SHA，锁定版本，两臂同份输入。跨版本基线重新建立。
首版规模 / OSLinux 三架构 manager、RV64 worker 已设计；16 worker/1000 ready case 是建议目标。Windows/macOS manager、HA、私有 hidden 输入都需要新增范围与验收。
